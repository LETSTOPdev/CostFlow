# Partner data intake & session checklist

Partner code: ______ · Session date: ______ · Operator: ______

## 0. Preconditions

- [ ] `pnpm check` green on the current commit (record the commit hash: ______)
- [ ] Guardrail test green (`partner-guardrail.test.ts`) — partner-runs/ is ignored
- [ ] Files received over an agreed private channel, stored in `raw/`, originals never edited
- [ ] Salt generated by `new-run.sh` (never regenerate mid-engagement; pseudonyms must stay stable)

## 1. File inspection (record in notes/session-log.md — values-free)

For each file: name, size, row count (`wc -l`), header (`head -1`), encoding
(`file`), delimiter, date format(s) observed, obvious oddities.

- [ ] Items file inspected
- [ ] Events file inspected (if any)
- [ ] Date formats ISO? If not: record format; a deterministic pre-transform will
      be needed (document every transformation; keep originals in `raw/`)

## 2. Mapping classification

Classify EVERY column / requested mapping as exactly one of:

| Classification | Meaning                                                                    |
| -------------- | -------------------------------------------------------------------------- |
| direct         | maps 1:1 to a canonical field                                              |
| derived        | deterministically computable (document the rule)                           |
| assumption     | needs a customer-confirmed input (rate, threshold, value)                  |
| unsupported    | canonical model has no seat for it — record as a finding, do NOT improvise |

- [ ] Classification table completed in notes (column names only — no values)
- [ ] Status values enumerated and mapped to stage kinds with the partner
- [ ] Actor→role map built WITH the partner. Never guess a role from a name,
      email domain, or title-like string — no explicit confirmation, no mapping
- [ ] Rate card and thresholds confirmed by the partner (provenance: customer)

## 3. Execution passes (strict order; stop at first insufficient pass)

- [ ] **Pass 1 — structural preflight** (`costflow preflight`, no financials).
      Record: required columns, duplicate headers, duplicate ids, date
      parseability, mapping coverage, actor-role coverage, event referential
      integrity, unsupported fields, dropped rows + reasons.
      Gate: do NOT proceed to costing if structure is insufficient.
- [ ] **Pass 2 — F2-only baseline** (no `--events`). Record diagnostics,
      capability profile, findings, estimates, confidence limits, assumption
      inventory, unresolved mapping questions. This baseline stands even if
      events later fail.
- [ ] **Pass 3 — F1+F2** (add `--events`). If strict validation fails:
      preserve the exact failure text; classify it (data quality / export
      semantics / mapping / unsupported product behavior); NO silent repair,
      NO validation relaxing. A justified deterministic correction = new
      transformed copy in `config/derived/` + a documented transformation
      note; `raw/` stays untouched.
- [ ] **Pass 4 — privacy verification** (`verify-privacy.sh`): list every raw
      actor value in a LOCAL values file (`config/actor-values.txt`, ignored),
      grep all outputs and notes. Required result: 0 occurrences. Report
      counts only.
- [ ] **Pass 5 — reproducibility**: identical re-run, `cmp` on run.json,
      report.md, and captured preflight output. Required: byte-identical.

## 4. Session wrap

- [ ] Findings memo drafted (`notes/findings-memo.md`) while memory is fresh
- [ ] Partner told what is retained (artifacts incl. titles + rate card) and
      the deletion procedure
- [ ] Nothing under partner-runs/ staged or committed (`git status` clean)
- [ ] Decision recorded: keep local data for follow-up session, or run
      `cleanup.sh` now
